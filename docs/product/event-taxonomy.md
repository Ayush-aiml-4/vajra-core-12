# VAJRA — Security Event Model & Taxonomy

**Document Status:** Product & Engineering Specification (Prompt 0002 — `PLANNED`)  
**Related Modules:** VAJRA Guard, VAJRA Locate, VAJRA Recover, ThreatCheck, VAJRA Risk Engine, Security Timeline

## 1. Canonical Security Event Envelope

Every event generated by a trusted device agent (Windows or Android) or internal VAJRA subsystem (Backend Auth, Command Engine, ThreatCheck) conforms to a unified, strongly typed schema before persistence and timeline indexing.

```json
{
  "eventId": "evt_01J9Z8K4M2N6P8Q0R2S4T6V8W0",
  "userId": "usr_94a1c02e-7b1a-4c9f-8e2d-112233445566",
  "deviceId": "dev_3f8b2a10-5c4d-4e6a-9b8c-77889900aabb",
  "category": "SECURITY",
  "eventType": "SECURITY_CONFIGURATION_CHANGED",
  "severity": "HIGH",
  "timestamp": "2026-10-06T18:04:12.410Z",
  "ingestedAt": "2026-10-06T18:04:12.890Z",
  "source": "WINDOWS_AGENT",
  "signatureVerified": true,
  "riskScoreDelta": 25,
  "riskScoreAfter": 72,
  "summary": "Windows Defender real-time protection was turned off.",
  "metadata": {
    "subcomponent": "WindowsDefender",
    "previousState": "ENABLED",
    "currentState": "DISABLED",
    "osEventId": 5001
  }
}
```

### 1.1 Envelope Field Definitions

| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `eventId` | `string` (UUID / ULID) | Yes | Globally unique, time-sortable event identifier. |
| `userId` | `string` (UUID) | Yes | Owning account identifier. |
| `deviceId` | `string` (UUID \| `null`) | Conditional | Target or originating device ID (`null` for account-level events such as `URL_CHECK_REQUESTED`). |
| `category` | `EventCategory` | Yes | High-level grouping (`AUTHENTICATION`, `DEVICE`, `SECURITY`, `RECOVERY`, `THREATCHECK`). |
| `eventType` | `EventType` | Yes | Specific canonical event code from the extensible taxonomy below. |
| `severity` | `EventSeverity` | Yes | `INFO`, `LOW`, `MEDIUM`, `HIGH`, or `CRITICAL`. |
| `timestamp` | `string` (ISO-8601 UTC) | Yes | Timestamp when the event occurred on the source endpoint or service. |
| `ingestedAt` | `string` (ISO-8601 UTC) | Yes | Timestamp when `vajra-api` verified and recorded the event. |
| `source` | `EventSource` | Yes | `WINDOWS_AGENT`, `ANDROID_AGENT`, `WEB_CONSOLE`, `BACKEND_WATCHDOG`, or `THREATCHECK_ENGINE`. |
| `signatureVerified` | `boolean` | Yes | `true` if the payload signature matched the active `DeviceCredential` public key (or internal backend authority). |
| `riskScoreDelta` | `number` | Yes | Contribution of this event to the device or account risk score ($0\text{–}100$). |
| `riskScoreAfter` | `number` | Yes | Resulting risk score ($0\text{–}100$) evaluated by the Risk Engine at ingestion time. |
| `summary` | `string` | Yes | Clean, human-readable one-line description displayed in the Security Timeline. |
| `metadata` | `Record<string, unknown>` | Yes | Sanitized, schema-validated key-value context passed through `sanitizeLogMetadata()`. |

## 2. Event Categories & Canonical Event Types

The taxonomy is designed to be **extensible**: new event types may be added under existing or future categories by registering their metadata schema and default severity/risk weights without breaking existing timeline queries.

### 2.1 Category: `AUTHENTICATION`
Tracks account and workstation authentication events. Passwords, PINs, or session tokens are never included in `metadata`.

| `eventType` | Default Severity | Typical Source | Description & Permitted Metadata |
| :--- | :--- | :--- | :--- |
| `LOGIN_SUCCESS` | `INFO` | `WINDOWS_AGENT` / `WEB_CONSOLE` | Successful interactive workstation login (Windows Event ID 4624) or VAJRA Web Console login. Metadata: `logonType` (e.g., Interactive, Unlock), `authMethod` (`PASSKEY`, `PASSWORD_MFA`, `OS_LOGON`). |
| `LOGIN_FAILURE` | `MEDIUM` (escalates to `HIGH` on burst) | `WINDOWS_AGENT` / `WEB_CONSOLE` | Failed login attempt (Windows Event ID 4625 or Web Console auth failure). Metadata: `failureCountWindow`, `logonType`, `reasonCode` (never the attempted password). |
| `ACCOUNT_CHANGE` | `HIGH` | `WEB_CONSOLE` / `WINDOWS_AGENT` | Security-relevant account modification, such as new Passkey registered, MFA reconfigured, recovery profile updated, or local Windows administrator group membership change. |

---

### 2.2 Category: `DEVICE`
Tracks availability, lifecycle, and physical session state of enrolled endpoints.

| `eventType` | Default Severity | Typical Source | Description & Permitted Metadata |
| :--- | :--- | :--- | :--- |
| `DEVICE_ONLINE` | `INFO` | `WINDOWS_AGENT` / `ANDROID_AGENT` | Device established or resumed signed heartbeat check-ins with `vajra-api`. Metadata: `agentVersion`, `batteryPct` (if applicable). |
| `DEVICE_OFFLINE` | `LOW` (or `HIGH` if unexpected/Lost Mode) | `BACKEND_WATCHDOG` / `WINDOWS_AGENT` | Device missed its heartbeat threshold window or reported a graceful shutdown. Metadata: `lastHeartbeatAt`, `reason` (`HEARTBEAT_TIMEOUT`, `GRACEFUL_SHUTDOWN`). |
| `DEVICE_LOCKED` | `INFO` | `WINDOWS_AGENT` / `ANDROID_AGENT` | Workstation locked (Windows Event ID 4800) or Android interactive screen locked with secure Keyguard. |
| `DEVICE_UNLOCKED` | `INFO` | `WINDOWS_AGENT` / `ANDROID_AGENT` | Workstation unlocked (Windows Event ID 4801) or Android Keyguard unlocked by user (`ACTION_USER_PRESENT`). |

---

### 2.3 Category: `SECURITY`
Tracks endpoint security posture changes, peripheral connections, network changes, and agent health.

| `eventType` | Default Severity | Typical Source | Description & Permitted Metadata |
| :--- | :--- | :--- | :--- |
| `SECURITY_CONFIGURATION_CHANGED` | `HIGH` / `CRITICAL` | `WINDOWS_AGENT` / `ANDROID_AGENT` | Change in Windows Defender status, Firewall profile, BitLocker state, Android screen-lock security, or Android ADB/Developer mode state. Metadata: `component`, `previousState`, `currentState`. |
| `USB_DEVICE_DETECTED` | `LOW` (or `MEDIUM` when locked) | `WINDOWS_AGENT` | External USB device connected to Windows PC. Metadata: `deviceClass` (`MassStorage`, `HID`, `Other`), `vendorId`, `productId`, `workstationLockedAtTime`. File contents on the USB drive are never accessed. |
| `NETWORK_CHANGED` | `INFO` / `MEDIUM` | `WINDOWS_AGENT` / `ANDROID_AGENT` | Device switched network interfaces or joined a new network profile. Metadata: `networkCategory` (`PUBLIC`, `PRIVATE`, `DOMAIN`, `CELLULAR`, `VPN`), `isNewNetworkHash`. |
| `SECURITY_AGENT_STOPPED` | `HIGH` | `WINDOWS_AGENT` / `BACKEND_WATCHDOG` | VAJRA service reported a stop signal or terminated unexpectedly. Metadata: `stopReason` (`SERVICE_CONTROL_STOP`, `UNEXPECTED_EXIT`, `WATCHDOG_MISSING`). |

---

### 2.4 Category: `RECOVERY`
Tracks lost-device protection and remote recovery workflows.

| `eventType` | Default Severity | Typical Source | Description & Permitted Metadata |
| :--- | :--- | :--- | :--- |
| `LOST_MODE_ENABLED` | `CRITICAL` | `WEB_CONSOLE` / `ANDROID_AGENT` | User activated Lost Mode for a device. Metadata: `commandId`, `customMessageConfigured` (`boolean`). |
| `LOST_MODE_DISABLED` | `INFO` | `WEB_CONSOLE` / `ANDROID_AGENT` | Lost Mode deactivated by authenticated user in Web Console or after local OS unlock on device. Metadata: `deactivatedBy` (`WEB_CONSOLE`, `DEVICE_OWNER_UNLOCK`). |
| `RING_REQUESTED` | `MEDIUM` | `WEB_CONSOLE` | Authenticated user issued `RING_PHONE` command. Metadata: `commandId`, `issuerUserId`. |
| `RING_ACKNOWLEDGED` | `INFO` | `ANDROID_AGENT` | Android phone verified the `RING_PHONE` signature and began audible ringing (or reported OS audio restriction). Metadata: `commandId`, `executionStatus`. |

---

### 2.5 Category: `THREATCHECK`
Tracks URL and domain threat analysis requests and detections.

| `eventType` | Default Severity | Typical Source | Description & Permitted Metadata |
| :--- | :--- | :--- | :--- |
| `URL_CHECK_REQUESTED` | `INFO` | `WEB_CONSOLE` | User submitted a URL for ThreatCheck analysis. Metadata: `redactedUrl` (query secrets stripped), `hostname`, `analysisMode` (`STANDARD_PASSIVE`). |
| `URL_ANALYSIS_COMPLETED` | `INFO` / `LOW` | `THREATCHECK_ENGINE` | ThreatCheck completed analysis with `SAFE`, `LOW`, or `UNKNOWN` risk level. Metadata: `threatCheckId`, `riskScore`, `riskLevel`. |
| `THREAT_DETECTED` | `HIGH` / `CRITICAL` | `THREATCHECK_ENGINE` | ThreatCheck identified `MEDIUM`, `HIGH`, or `CRITICAL` threat indicators (e.g., phishing, homograph attack, known malware distribution). Metadata: `threatCheckId`, `riskScore`, `riskLevel`, `matchedIndicators`. |

## 3. Event Sanitization & Schema Validation Rules

1. **Strict Enum & Schema Validation:** Unknown `category` values are rejected. Unknown `eventType` strings outside the registered taxonomy are rejected unless explicitly versioned under a forward-compatible extension schema.
2. **Automatic Secret Redaction:** Before any `SecurityEvent` is written to PostgreSQL or emitted over WebSockets, its `metadata` object is passed through `sanitizeLogMetadata()` (`@vajra/security`) to ensure keys matching `password`, `secret`, `token`, `key`, `authorization`, `cookie`, or `credential` are replaced with `[REDACTED]`.
3. **Payload Size Cap:** Individual event `metadata` JSON objects are capped at `4 KB` to prevent database bloat or denial-of-service via oversized telemetry payloads.
